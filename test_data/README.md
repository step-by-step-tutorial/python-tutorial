<h1 align="center">Test Data Generator</h1>

Generates realistic test datasets from JSON configs and plain text source files, and writes them as CSV, JSON or XML
files, to a PostgreSQL table, or to a Kafka topic. A small REST API lists, generates and downloads the datasets.
The generated data feeds `data_platform`.

```text
Test Data Generator
    read a dataset config from config/<name>.json
    build one generator per column and order the columns by their dependencies
    generate row_count rows
    write the rows to every configured destination (csv, json, xml, database, kafka)
```

## Project Structure

```text
test_data
├── config/                      one JSON config per dataset
├── data/                        source files the columns pick values from
├── scripts/database/            database schema created by Docker
├── src/test_data
│   ├── cli.py                   command line entry point (python -m test_data)
│   ├── api/                     REST API
│   ├── model/                   data models, one per file: settings, column, config and API models
│   ├── generator/               dataset and row generators
│   ├── generator/column/        column generators by kind and their registry
│   ├── writer/                  csv, json, xml, database and kafka writers, and the writer registry
│   ├── repository/              configured datasets, source files and database access
│   ├── connector/               Kafka producer and publishing
│   └── util/                    file, csv, json, xml, date, text, formula and validation helpers
└── tests
```

All commands below run from the repository root.

## 3. Configure a Dataset

Each file in [config](config) is one dataset; its name without `.json` is the dataset name.

```json
{
  "row_count": 500,
  "output_name": "house",
  "kafka_topic": "house.events.v1",
  "kafka_key_column": "property_id",
  "destinations": ["csv", "json", "database", "kafka"],
  "columns": [
    { "name": "property_id", "type": "sequence", "start": 100000, "step": 1 },
    { "name": "property_type", "type": "random_from_file", "file": "data/property_types.txt" }
  ]
}
```

A column is generated by its `method` if set, otherwise by its `type`. Any column can be `"nullable": true` with an
optional `null_probability` (default 0.2), and any column can have `"present_when": "<boolean column>"` to stay blank
unless that column is `True` (for example `garage_capacity` only when `has_garage`).

| Generator                     | Required fields                                                                 |
|-------------------------------|---------------------------------------------------------------------------------|
| `sequence`                    | optional `start`, `step` (default 1)                                            |
| `fixed`                       | `value`                                                                         |
| `random_int`, `random_float`  | `min` or `min_field`, `max` or `max_field` (a `_field` reads the bound from another column) |
| `random_bool`                 |                                                                                 |
| `random_date`, `random_timestamp` | `date_start`, `date_end` (YYYY-MM-DD)                                       |
| `random_from_file`            | `file`: one value per line                                                      |
| `random_from_directory`       | `file`: a directory; optional `exclude_directories`                             |
| `random_from_mapped_file`     | `source_field`, `mapping_file`, `key_column`, `file_column` or `file_columns`   |
| `random_from_mapped_csv`      | `source_field`, `key_column`, `mapping_file` or `file_template`, `value_column` or `value_template` |
| `lookup_from_csv`             | `source_field`, `mapping_file`, `key_column`, `value_column`                    |
| `email_from_source_fields`    | `source_fields`, optional `domain`                                              |
| `concat_from_source_fields`   | `source_fields`, optional `separator`                                           |
| `product_of_source_fields`    | `source_fields`, optional `value` as an extra factor                            |
| `formula`                     | `source_fields`, `formula`: arithmetic over `values[0]`, `values[1]`, ...       |
| `date_with_random_day_offset` | `source_field` (a date or a timestamp), optional `min`, `max` days (default 1 to 7) |

Columns that read source fields are generated after those fields, whatever their order in the config. Each column
has its own random stream (seeded from `RANDOM_SEED` and the column name), so the output is the same on every run.

## 4. Test

```shell
pytest ./test_data
```

## 5. Start the Infrastructure

Needed only for the `database` and `kafka` destinations: PostgreSQL, Adminer, Kafka and Kafdrop.

```shell
docker compose --file ./test_data/docker-compose-infrastructure.yml --project-name test --env-file ./test_data/.env.test up --build -d
```

## 6. Generate Datasets

```shell
python -m test_data --config online_shopping
python -m test_data --config house
python -m test_data
python -m test_data --help
```

`--config` takes a dataset name or a path to a config file; without it, every config is generated. Files are
written to `./test_data/output`. If any destination fails, the others are still written and the command exits
with an error.

## 7. Run the API

```shell
PORT=8084 python -m test_data.api.dataset_api
```

* API: [localhost:8084](http://localhost:8084)
* Swagger UI: [localhost:8084/docs](http://localhost:8084/docs)
* ReDoc: [localhost:8084/redoc](http://localhost:8084/redoc)

| Method | Path                                    | Description                                   |
|--------|-----------------------------------------|-----------------------------------------------|
| GET    | `/health`                               | service status and version                    |
| GET    | `/datasets`                             | metadata of every dataset                     |
| GET    | `/datasets/names`                       | dataset names                                 |
| GET    | `/datasets/{name}`                      | metadata of one dataset                       |
| POST   | `/datasets/{name}/generate`             | generate the dataset                          |
| GET    | `/datasets/{name}/rows?page=&page_size=` | read generated rows from the database         |
| GET    | `/datasets/{name}/download?format=csv`  | download a generated csv, json or xml file    |

## 8. Stop the Infrastructure

```shell
docker compose --file ./test_data/docker-compose-infrastructure.yml --project-name test --env-file ./test_data/.env.test down -v
```

## 9. Run with Docker

Runs the infrastructure and the generator; the container generates every dataset, then serves the API on port 8084.

```shell
docker compose --file ./test_data/docker-compose.yml --project-name dev --env-file ./test_data/.env.dev up --build -d
```
